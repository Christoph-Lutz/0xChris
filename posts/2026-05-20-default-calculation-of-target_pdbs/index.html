The trace output (from 23.26.0) shows that Oracle determines the SGA size using the function kmgsb_get_sga_size, which returns 45097156608 (42G). This value is then divided by 512M (536870912 bytes). Based on this observation, the formula described in My Oracle Support note PALRT1151 does not appear to reflect the actual target_pdbs calculation used by Oracle, since Oracle no longer applies the 2× multiplier and instead simply divides the SGA size by 512M.

📝 Behavior in Older Releases

A quick check on 12.2.0.1, 19.8, and 19.26 (test results not shown here) confirms that the target_pdbs calculation in 12cR2 and 19c is identical to the behavior observed in 26ai above.

This is particularly interesting because My Oracle Support notes KI28384 and KI38982 (see also sources 2 and 3) both state that bug fixes 31061145 and 36501568, respectively, would change the algorithm used to derive the target_pdbs value:

“This fix provides a better algorithm for setting the default value of TARGET_PDBS, so that customers do not need to manually set it."

However, as 12.2.0.1, 19.8, and 19.26 (with fix 36501568 applied) all exhibit the same behavior, this indicates that the formula provided in My Oracle Support note PALRT1151 is not correct, and raises the question of whether the algorithmic changes mentioned in notes KI28384 and KI38982 refer to the target_pdbs calculation or to a different change.
